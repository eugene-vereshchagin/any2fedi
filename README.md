# any2fedi

**[English version](README.en.md)**

Зеркалит чужие ленты в федиверс: публичные Telegram-каналы и RSS/Atom уходят в бот-аккаунты на вашем сервере (GoToSocial, Mastodon, Akkoma, Pleroma — любой с Mastodon API).

- **Аккаунт** — один бот на сервере, один токен.
- **Источник** — одна лента: Telegram-канал или RSS/Atom.
- В один аккаунт можно свести сколько угодно источников, и аккаунтов тоже может быть сколько угодно. Например, `@news` собирает три новостных канала, а `@blog` перепощивает RSS какого-нибудь сайта.

Telegram читается через веб-превью `https://t.me/s/<канал>`. Не нужны ни бот, ни аккаунт, ни API-ключи. Работает с любым публичным каналом, у которого открыт предпросмотр.

Один файл на Python, три зависимости из репозиториев дистрибутива, sqlite для состояния, systemd-таймер. Ни контейнеров, ни демонов.

## Возможности

- Форматирование (жирный, курсив, ссылки, цитаты, код) переводится в Markdown.
- Картинки и альбомы перезаливаются на сервер.
- Видео, файлы и опросы не копируются: к посту прикладывается превью-кадр, ставится пометка и ссылка на оригинал. Посты, где только видео без подписи, по умолчанию пропускаются.
- Репосты помечаются.
- В каждом посте есть подпись источника и ссылка на оригинал.
- **Все формулировки в постах задаются в конфиге** (секция `texts`) и переопределяются на уровне аккаунта или отдельного источника.
- Новый источник не вываливает в ленту свою историю: уже существующие посты пропускаются (или публикуется `backfill` последних).
- Дубли исключены: состояние хранится в sqlite, плюс к каждому посту передаётся `Idempotency-Key`.
- Если сервер недоступен или отвечает 5xx, пост повторяется на следующем прогоне, порядок сохраняется. Если сервер отверг пост (4xx), он пропускается и пишется в лог, чтобы очередь не вставала.
- Правки и удаления в оригинале не отслеживаются.

## Установка

Инструкция для Debian/Ubuntu.

```bash
sudo apt install python3-requests python3-bs4 python3-yaml git

sudo useradd --system --home /srv/any2fedi --shell /usr/sbin/nologin any2fedi
sudo git clone https://github.com/<you>/any2fedi.git /srv/any2fedi
sudo mkdir -p /srv/any2fedi/state
sudo cp /srv/any2fedi/config.example.yaml /srv/any2fedi/config.yaml
sudo chown -R any2fedi:any2fedi /srv/any2fedi
sudo chmod 600 /srv/any2fedi/config.yaml
```

### 1. Бот-аккаунт на сервере

Заведите на сервере обычный аккаунт под бота. В GoToSocial с закрытой регистрацией это делается через CLI:

```bash
./gotosocial --config-path ./config.yaml admin account create \
  --username news --email news@your.domain --password 'длинный-пароль'
./gotosocial --config-path ./config.yaml admin account confirm --username news
```

Затем зайдите под ботом в настройки профиля:
- отметьте **«Это бот»** (bot account);
- выключите ручное одобрение подписчиков, чтобы подписаться мог кто угодно;
- в описании укажите, откуда берутся посты: «Неофициальное зеркало каналов …».

### 2. Токен

```bash
python3 /srv/any2fedi/get_token.py https://your.instance
```

Скрипт выдаст ссылку. Откройте её в браузере, **залогиньтесь под ботом** (удобнее в приватном окне), подтвердите доступ и вставьте код обратно в терминал. Полученный токен впишите в `config.yaml`.

### 3. Конфиг

Всё описано в комментариях в [`config.example.yaml`](config.example.yaml). Готовый пример на русском: [`examples/georgia-news.ru.yaml`](examples/georgia-news.ru.yaml).

### 4. Проверка вхолостую

```bash
sudo -u any2fedi python3 /srv/any2fedi/any2fedi.py --dry-run -c /srv/any2fedi/config.yaml
```

Команда скачает ленты и выведет по 3 последних поста из каждого источника ровно в том виде, в каком они уйдут на сервер. Ничего не публикует, состояние не трогает.

### 5. Таймер

```bash
sudo cp /srv/any2fedi/systemd/any2fedi.{service,timer} /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now any2fedi.timer
journalctl -u any2fedi -f
```

Прогон идёт раз в 10 минут. Первый прогон только запоминает, что уже есть в лентах, публикация начинается со следующих постов.

## Тексты в постах

Каждый пост собирается по шаблону из блоков. Пустые блоки исчезают вместе с пустыми строками вокруг.

```yaml
texts:
  template: "{text}\n\n{forwarded}\n\n{media_note}\n\n{footer}\n\n{hashtags}"
  footer: "— {source}: {url}"
  forwarded: "↪ переслано из: {name}"
  unsupported_media: "🎬 видео / вложение — в оригинале"
  truncated: "… (полностью — в оригинале)"
  rss_title: "**{title}**"
```

Ключи можно переопределить в `accounts.<имя>.texts` или в `sources[].texts`. Заменяются только те ключи, которые вы указали, остальные наследуются. Порядок приоритета такой: встроенные значения → `texts` → аккаунт → источник.

## Расширение

- **Ещё источник в аккаунт** — строка в `sources`.
- **Ещё аккаунт** — заведите бота, получите токен и добавьте блок в `accounts`.
- **Новый тип источника** (сайт без RSS, другой сервис) — класс-наследник `Source` в `any2fedi.py` с методом `fetch()`, который возвращает список `Item`, плюс регистрация в `SOURCE_TYPES`.

Внутреннее имя аккаунта (ключ в `accounts`) и адрес источника используются как ключи в базе состояния. Если их переименовать, источник будет считаться новым: история не задублируется, просто начнётся с текущего момента.

## Ограничения

- `t.me/s/` отдаёт около 20 последних постов. Если канал публикует больше 20 постов за интервал таймера, лишнее пропадёт. Для таких каналов уменьшите интервал.
- Это парсинг HTML: если Telegram поменяет вёрстку, парсер придётся поправить.
- В пределах одного прогона посты из разных источников идут группами по источникам, а не строго по времени.
